Connect your own tomorrow.

The synthetic demo works immediately. To use your own apps, configure a Google OAuth web client and connect your account. You stay in control of every Calendar action.

Google setup

  1. Open Google Cloud Console with 2-Step Verification enabled. Create a dedicated project.
  2. Enable Gmail API, Google Calendar API, Google Sheets API, and Google Drive API. Drive supports recovery of the app-created spreadsheet; no broader Drive permission is requested.
  3. In Google Auth Platform, name the app Dayweave. Select External, keep it in Testing, and add your account as a test user.
  4. Add these permissions: openid, userinfo.email, gmail.readonly, calendar.events.owned, and drive.file. For the full scope URLs, see the repository setup guide linked below.
  5. Create a Web application OAuth client. Add authorized JavaScript origins http://localhost:5173, http://localhost:4173, and https://jsohlot.github.io. Do not include the repository path in the origin.
  6. Copy the public client ID into Dayweave's app settings. Never enter a client secret. Connect Google and personally approve the requested permissions.

Enable AI planning

Create a key in Google AI Studio, paste it into Dayweave's Gemini key field, and review the data-sharing consent. The key stays only in this page session. Keep real sensitive data out of free-tier testing; use synthetic data for the hackathon demonstration.

No Gemini key? The app still shows a clearly labeled deterministic planning preview. It never claims a successful AI request when one did not complete.

First run

Set your routines, save preferences explicitly to create the app's workbook, and generate tomorrow's plan. Inspect the evidence and select only the events you want. Review the exact times before confirming. Verify successful actions through the Calendar and Sheets links.

If a connection fails

An origin error means the exact page origin is missing from the Google client. An access-denied error can mean your account is not a test user or a required permission was omitted. A 403 can mean the relevant API is disabled. An expired session requires reconnecting; the app does not store refresh tokens.
